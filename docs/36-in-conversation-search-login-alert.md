# 대화 내 검색 · 새 기기 로그인 알림

## 1. 대화 내 검색

기존에는 사이드바의 **전역 검색**만 있었습니다. 이제 대화 헤더의 **검색** 버튼으로
현재 대화 안에서만 찾을 수 있습니다.

| 항목 | 결정 |
|---|---|
| 데이터 소스 | `client/src/lib/search.ts` 의 로컬 인덱스(IndexedDB `onemoments-search`) — 서버 무관 |
| 범위 | `searchMessages(query, { conversationId })` 로 **현재 대화만** 조회 |
| 결과 | 최대 30건, 최신순. 상대 시간 + 본문 2줄 |
| 이동 | 결과를 누르면 기존 `?anchor=<messageId>` 흐름으로 **페이지 로드 → 스크롤 → 하이라이트** |
| 디바운스 | 200ms, 대화 전환 시 검색 상태 초기화 |

> 한계: 검색 인덱스에는 **이 기기에서 한 번이라도 복호화된 메시지**만 들어갑니다.
> 전역 검색과 동일한 제약이며, 오래된 메시지는 한 번 열어 보면 인덱싱됩니다.

## 2. 새 기기 로그인 알림(Web Push)

비밀번호 로그인에서 **기존 활성 기기가 있는데 새 기기를 등록**한 경우, 사용자의
**다른 기기**로 보안 알림을 보냅니다.

| 항목 | 결정 |
|---|---|
| 트리거 | `POST /api/auth/login` 에 `device`(새 키)를 보내 기기를 새로 등록했고, 활성 기기가 이미 1대 이상일 때 |
| 대상 | 같은 사용자의 활성 기기 구독 중 **방금 로그인한 기기 제외**(`excludeDeviceId`) |
| 페이로드 | `{ type: "security", title, body: "새 기기에서 로그인했습니다: <기기 이름>", tag: "onemoments-security", url: "/devices" }` |
| 프라이버시 | 대화·메시지·IP 등은 담지 않는다. 기기 이름은 사용자가 붙인 값(40자 제한) |
| 실패 처리 | `void` 로 보내 로그인 응답을 지연시키지 않는다(전송 실패는 로그만 남김) |
| 알림 클릭 | 서비스 워커가 `data.url` 을 우선 사용해 **`/devices`** 로 이동 → 즉시 폐기 가능 |

### 서비스 워커 변경

`client/public/sw.js` 의 알림 데이터에 `url` 을 추가하고, 클릭 시 `data.url`(내부 경로)을
우선 사용합니다. 기존 메시지·통화 알림은 `conversationId` 로 동작하므로 변화가 없습니다.

### 알림이 오지 않는 경우

- 이미 로그인한 기기에서 재로그인(`deviceId` 전달) — 새 기기가 아니므로 알림 없음
- 첫 기기 등록(가입·첫 로그인) — 비교 대상이 없으므로 알림 없음
- 해당 계정에 푸시 구독이 없는 경우(브라우저 알림 미허용, 다른 기기 로그아웃 등)
- `VAPID_*` 미설정 서버(푸시 비활성)
