# X3DH signed prekeys

1:1·그룹 배포의 **최초 v2 세션**은 상대 기기의 **signed prekey(SPK)** 가 있으면 X3DH로 초기화한다.
SPK가 없는 구버전 기기는 기존 정적 X25519 초기화로 fallback한다.

## 1. 키

| 키 | 위치 | 용도 |
|---|---|---|
| IK | 기기 identity X25519 | 장기 신원 |
| SPK | 기기별 X25519 | X3DH signed prekey |
| SPK 서명 | Ed25519 기기 서명키 | 서버·클라이언트 검증 |
| EK | 메시지마다 새 X25519 | X3DH ephemeral |

SPK는 기기 등록 시 함께 업로드하고, 서버가 `onemoments-signed-prekey:{id}:{publicKey}` 서명을 검증한다.
기존 기기는 로그인/복구 후 `PUT /api/auth/device/prekey`로 SPK를 추가 업로드한다.

## 2. X3DH

발신자(A), 수신자(B):

```
DH1 = EK_A × SPK_B
DH2 = EK_A × IK_B
DH3 = IK_A × SPK_B
DH4 = EK_A × OPK_B   (OPK가 있을 때)
shared = HKDF-SHA256(salt=0^32, DH1 || DH2 || DH3 [|| DH4], info="onemoments/dr/root-v1")
```

- 최초 v2 봉투에 `senderIdentityPublicKey`(IK_A), `signedPreKeyId`(SPK_B), 선택적으로 `oneTimePreKeyId`(OPK_B)를 저장한다.
- 수신자는 같은 순서로 DH를 계산해 root/chain을 초기화한다.
- OPK는 서버가 메시지 저장 시 1회 사용 표시하고, 기기 번들에서 미사용 OPK를 하나씩 노출한다.
- 기기 로드 시 서버의 미사용 OPK 수를 확인해 20개 목표로 보충하며, 사용된 private 키는 최근 이력 복호화를 위해 보존한다.
- 이후 메시지는 기존 Double Ratchet DH 래칫을 그대로 사용한다.
- 세션이 이미 있으면 X3DH 헤더를 다시 보내지 않는다.

## 3. 서버

| 컬럼 | 의미 |
|---|---|
| `devices.signed_pre_key_id/public_key/signature` | 기기별 SPK |
| `message_keys.sender_identity_public_key` | 최초 봉투의 IK_A |
| `message_keys.signed_pre_key_id` | 사용한 SPK_B |

- 서버는 SPK 서명을 검증하지만 DH/root는 계산하지 않는다.
- 대화 기기 번들 응답(`GET /api/conversations/:id/devices`)에 SPK 공개키/서명을 포함한다.
- 기존 기기는 SPK가 null이며 v2 정적 초기화로 계속 동작한다.

## 4. 백업

- SPK와 **OPK private**를 키 백업에 포함한다. 복구 기기는 기존 세션과 새 X3DH 봉투를 모두 처리할 수 있다.
- SPK는 30일이 지나면 자동 회전하며, 이전 SPK private는 복호화용으로 최대 5개 보관한다.
- 구버전 백업(SPK/OPK 없음)은 복구 후 새 키를 생성·업로드한다.

## 5. 한계·후속

| 항목 | 현재 |
|---|---|
| 원타임 프리키(OPK) | **구현** — 서버가 사용 표시, 클라이언트 20개 목표 보충 |
| SPK 회전 | 30일 자동 회전(이전 키 5개 보관). 수동 회전 UI는 없음 |
| 다중 기기 | 기기별 SPK/OPK로 지원 |
| 서명 검증 | 서버가 등록 시 검증, 클라이언트는 서버 번들을 신뢰 |
| 재전송/멱등 | 기존 clientMessageId 멱등 경로 유지. 동시 사용 OPK는 드물게 재사용될 수 있음 |
| 1:1 fallback | SPK 없는 기기는 정적 X25519(기존 v2) |
