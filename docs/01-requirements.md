# 요구사항 — OneMoments

## 용어

| 용어 | 의미 |
|---|---|
| 기기 | 브라우저 프로필 단위. X25519 키 쌍을 가진다 |
| 봉투(envelope) | 수신 기기별로 감싼 메시지 키 + 발신 임시 공개키 |
| 안전번호 | 두 사용자의 기기 공개키를 해시한 지문(대면/음성으로 대조) |

## 기능 요구사항 (MVP)

### FR-01 가입

- username(3~32자, 소문자 정규화), password(10자 이상)로 가입한다.
- 가입 시 브라우저에서 기기 키 쌍을 만들고 **공개키만** 서버에 등록한다.
- 수용 기준
  - [ ] 같은 username(대소문자 무시) 재가입은 409
  - [ ] 비밀번호는 서버에 해시로만 저장된다
  - [ ] 가입 응답에 개인키가 포함되지 않는다

### FR-02 로그인·세션

- username/password 로그인, 로그아웃, 내 정보 조회.
- 세션은 **HttpOnly·Secure·SameSite 쿠키**로 유지한다(토큰을 JS 저장소에 두지 않는다).
- 수용 기준
  - [ ] 잘못된 비밀번호는 401(계정 존재 여부 비노출)
  - [ ] 로그아웃 후 기존 세션으로 API 호출 시 401
  - [ ] 세션 만료 후 자동 로그아웃 안내

### FR-03 기기·키 관리

- 내 기기 목록(이름·등록일·최근 접속), 기기 폐기.
- 수용 기준
  - [ ] 폐기된 기기의 세션은 즉시 무효
  - [ ] 다른 사용자는 내 기기 공개키를 조회할 수 없다(대화 상대 예외)

### FR-04 사용자 검색·1:1 대화

- username 정확 일치 검색, 자기 자신 제외.
- 같은 상대와는 기존 1:1 대화를 재사용한다.
- 수용 기준
  - [ ] 반복 생성 시 대화 ID 동일
  - [ ] 검색 결과에 이메일 등 추가 개인정보가 없다

### FR-05 메시지 전송 (E2E)

- 텍스트 메시지를 작성해 **클라이언트에서 암호화**한 뒤 전송한다.
- 수용 기준
  - [ ] 서버 요청/응답/DB 어디에도 평문이 없다
  - [ ] 수신 기기에서만 복호화된다
  - [ ] 같은 `clientMessageId` 재전송은 중복 저장되지 않는다
  - [ ] 봉투 크기 제한 초과는 413

### FR-06 실시간 수신·오프라인 동기화

- WebSocket 구독 중이면 즉시 수신, 아니면 재접속 시 이력에서 따라잡는다.
- 수용 기준
  - [ ] 온라인 상태에서 p95 300ms 이내 표시(동일 리전)
  - [ ] 상대 오프라인 중 보낸 메시지가 재접속 후 표시된다
  - [ ] 연결 끊김 후 재연결 시 누락 메시지가 중복 없이 복구된다

### FR-07 이력

- 커서 기반 페이지네이션(최신순), 이 기기에서 복호화 가능한 메시지만 표시.
- 수용 기준
  - [ ] 복호화 불가 메시지는 "이 기기에서 읽을 수 없음"으로 표시하고 평문을 추정하지 않는다
  - [ ] 50건 페이지 조회 p95 500ms 이내

### FR-08 안전번호

- 두 사용자의 활성 기기 공개키로 안전번호를 계산해 표시한다.
- 수용 기준
  - [ ] 상대 기기 키가 바뀌면 안전번호가 바뀌고 경고를 표시한다
  - [ ] 계산은 클라이언트에서만 수행한다

### FR-09 타이핑·접속 상태

- 같은 대화의 상대에게 타이핑/접속 상태를 중계한다(내용은 서버에 저장하지 않음).

### FR-10 삭제

- **대화 삭제**: 내 화면에서만 숨긴다(상대 이력·서버 데이터는 유지).
- **계정 삭제**: 로그인·기기·세션을 즉시 무효화하고 계정을 익명화한다. 내가 보낸 메시지는 상대 이력에 **"삭제된 사용자"** 로 유지된다.
- 수용 기준
  - [ ] 삭제된 계정으로 로그인·메시지 전송이 불가하다
  - [ ] 상대 화면에서 내 메시지는 유지되고 발신자가 "삭제된 사용자"로 표시된다
  - [ ] 삭제 즉시 내 기기 세션이 모두 종료된다
  - [ ] 대화 삭제는 상대 화면에 영향을 주지 않는다

## 비기능 요구사항

| ID | 항목 | 요구 |
|---|---|---|
| NFR-01 | 기밀성 | 서버는 평문·대화 키·기기 개인키를 저장/로그/응답에 포함하지 않는다. 자동 테스트로 검증 |
| NFR-02 | 전송 보안 | TLS 1.2+, HSTS, Secure·HttpOnly·SameSite 쿠키, 엄격한 CSP |
| NFR-03 | 인증 | 비밀번호는 scrypt 또는 Argon2id. 세션 ID 회전, 유휴 만료 |
| NFR-04 | 남용 방지 | 로그인/가입 레이트리밋, 사용자 검색 스로틀, 메시지 전송 레이트리밋 |
| NFR-05 | 성능 | 메시지 전송 p95 300ms, 이력 50건 p95 500ms(동일 리전) |
| NFR-06 | 확장성 | WebSocket 다중 인스턴스 전략을 M4까지 확정(sticky 또는 Redis 팬아웃) |
| NFR-07 | 관측성 | `/healthz`·`/readyz`, 구조화 로그(메타데이터만), 평문 금지 |
| NFR-08 | 백업 | 일일 백업 + PITR, 복구 리허설 절차 문서화 |
| NFR-09 | 접근성 | 키보드 탐색, 스크린리더 라벨, 색 대비(WCAG 2.1 AA 지향) |
| NFR-10 | 호환성 | 최신 Chrome·Edge·Safari·Firefox. WebCrypto X25519 미지원 시 검증된 라이브러리 폴백 |
| NFR-11 | 개인정보 | 최소 수집, 계정 삭제 요청 처리, 메타데이터 보존 기간 명시 |
| NFR-12 | 테스트 | 단위(암호·검증), 통합(API·WS), E2E(암복호화 왕복) 자동화 |
