# 프로필·연락처 (P1-A)

프로필 상태 메시지와 연락처 즐겨찾기·1:1 차단을 추가한다. 메시지·첨부·Moments 와 달리
**상태 메시지는 공개 프로필 메타데이터**이며, 즐겨찾기·차단은 사용자 쌍 메타데이터만
저장한다. 차단은 대화 내용을 읽거나 서버에서 분석하지 않고 전송 경로에서만 적용한다.

## 범위

- 공개 상태 메시지: 최대 80자, 빈 문자열/`null` 은 삭제
- 연락처 즐겨찾기: 대화 상대만 지정 가능, 대화 목록에서 즐겨찾기 우선 정렬
- 1:1 차단/해제: 차단한 사용자와는 양방향으로 메시지를 보낼 수 없고, 새 1:1 대화도 만들 수 없음
- 차단 시 즐겨찾기 자동 해제
- 상태 메시지는 대화 목록·채팅 헤더·연락처 화면에 표시

후속 범위: 프로필 아바타(암호화 이미지 배포 설계), 이메일 초대(메일 인프라), 그룹 단위 차단,
주소록 가져오기.

## 데이터 모델

| 테이블/컬럼 | 설명 |
|---|---|
| `users.status_message` | 공개 프로필 상태(평문, 최대 80자 CHECK). 메시지 암호화 대상 아님 |
| `user_blocks` | `blocker_user_id`, `blocked_user_id` (PK). 1:1 차단 메타데이터 |
| `user_favorites` | `user_id`, `favorite_user_id` (PK). 즐겨찾기 메타데이터 |

- 세 테이블 모두 사용자 삭제 시 `ON DELETE CASCADE` 로 정리된다.
- 메시지·봉투·첨부 테이블에는 어떤 컬럼도 추가하지 않는다.
- 마이그레이션: `0023_curvy_marvex.sql`

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| PUT | `/api/auth/profile` | `{statusMessage: string \| null}` 세션+CSRF 필요 |
| GET | `/api/contacts` | 내가 참여한 대화의 상대 목록 + 상태/즐겨찾기/차단 상태 |
| PUT | `/api/contacts/:userId/favorite` | `{favorite: boolean}` 대화 상대만 허용 |
| PUT | `/api/contacts/:userId/block` | `{blocked: boolean}` 대화 상대만 허용 |

응답 예시:

```jsonc
// GET /api/contacts
{
  "contacts": [
    {
      "id": "uuid",
      "username": "bob",
      "statusMessage": "coffee & code",
      "favorite": true,
      "blockedByMe": false,
      "blockedMe": false
    }
  ]
}
```

- 자기 자신은 즐겨찾기/차단할 수 없다(`400 INVALID_CONTACT`).
- 같은 대화에 참여한 적이 없는 사용자는 연락처로 취급하지 않는다(`404 CONTACT_NOT_FOUND`).
- 대화 요약(`ConversationSummary`)에 `favorite`, `blocked: "me" | "peer" | null` 이 추가된다.
  그룹 대화는 `favorite=false`, `blocked=null` 이다.

## 차단 동작

- 차단 관계(어느 방향이든)가 있으면 1:1 메시지 전송이 `403 USER_BLOCKED` 로 거절된다.
  REST 와 WebSocket 전송 모두 동일한 `sendEncryptedMessage` 경로를 사용한다.
- 차단 관계가 있으면 `POST /api/conversations` 로 기존 1:1 대화를 다시 열거나 새로 만들 수 없다.
- 기존 대화 이력은 삭제하지 않는다. UI 는 입력창 대신 차단 안내를 표시한다.
- **그룹 메시지에는 차단을 적용하지 않는다.** 그룹 참여자 집합과 차단 정책이 충돌할 수 있어
  후속 범위로 둔다.
- 읽음 표시·타이핑·presence 는 차단으로 변경하지 않는다.

## 상태 메시지의 프라이버시

- 상태 메시지는 **서버가 읽을 수 있는 공개 프로필 정보**다. 메시지·첨부·Moments 와 달리
  E2E 암호화 대상이 아니다. UI 에도 이 점을 명시한다.
- 대화 상대(같은 대화 참여자)에게만 `PeerUser.statusMessage` 로 내려간다. 사용자 검색 결과에는
  포함하지 않는다.
- 로그·에러에 상태 메시지 원문을 남기지 않는다.

## UI

- `/contacts` 페이지
  - 내 상태 메시지 편집(80자 카운터, 저장/해제)
  - 대화 상대 목록: 상태 메시지, 즐겨찾기 토글, 차단/해제(확인 다이얼로그), 대화 열기
  - 상대가 나를 차단한 경우 안내 표시
- 사이드바: `연락처` 진입점, 즐겨찾기 별표, 차단 상태 표시
- 채팅 헤더: 상대 상태 메시지, 차단 상태
- 채팅 입력창: 차단 시 전송 대신 안내 문구

## 운영·한계

- 추가 크론 작업이나 외부 인프라가 필요 없다.
- 차단 메타데이터는 사용자 쌍 정보이므로 백업에 포함된다. 계정 삭제 시 cascade 로 제거된다.
- 상태 메시지는 평문이므로 민감 정보를 넣지 않도록 UI 에서 안내한다.

## 이메일 초대·프로필 아바타 (추가 완료)

- **프로필 아바타**: 상태 메시지와 같은 공개 메타데이터로 서버에 평문 저장(128px JPEG, 64KB 이하).
  `PUT/DELETE /api/auth/profile/avatar`, `GET /api/users/:id/avatar`(ETag). 자세한 결정·한계는 [`31-profile-avatar.md`](31-profile-avatar.md).
- **이메일 초대**: 서버가 메일을 보내지 않는다. 그룹 초대 링크·앱 링크를 **`mailto:` 로 사용자의 메일 클라이언트**로 전달하고,
  이메일 주소는 수집·저장하지 않는다(계정 식별은 여전히 username). 근거: `state`/SMTP 인프라 없이도 초대 흐름을 유지하고,
  "개인정보 최소 수집" 원칙을 지킨다.
- **주소록 가져오기(연락처 동기화)는 보류**: 이메일·전화번호를 수집하지 않으므로 대조할 키가 없다.
  도입하려면 식별자 수집 정책(옵트인·해시·저장 기간)을 먼저 결정해야 한다.
