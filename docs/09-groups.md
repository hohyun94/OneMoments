# 그룹 대화

1:1 전제를 확장해 **최대 20명** 그룹을 지원한다. 서버는 여전히 평문·그룹 키를 모른다.

## 1. 현재 구현: 기기별 봉투

- 메시지마다 임의의 **콘텐츠 키**로 1회 암호화(AES-256-GCM)한다.
- 그 콘텐츠 키를 **참여자 전원의 활성 기기마다** X25519 ECDH + AES-GCM 봉투로 감싼다(발신자 자신의 다른 기기 포함).
- 메시지당 봉투 수 = 그룹 참여자들의 활성 기기 수. 그래서 그룹 인원을 20명으로 제한한다
  (`MAX_ENVELOPES` 기본 50, 기기 2~3대 기준).
- 새 참여자는 **참여 이후 메시지에만** 봉투가 생기므로 과거 이력은 복호화할 수 없다(의도된 동작).
- 기기 추가·참여자 추가로 활성 기기 집합이 바뀌면 서버가 `409 DEVICE_SET_CHANGED`로 재암호화를 요구하고,
  클라이언트는 기기 목록을 다시 받아 1회 재시도한다.

> **Sender Keys는 아직 아니다.** 로드맵의 “발신자 키”는 메시지를 1회만 암호화하고
> 참여자별 발신자 키 배포 메시지로 복호화하는 방식이다. 현재 구현은 단순성·기존 1:1 경로 재사용을 위해
> **수신자별 봉투**를 쓴다. Sender Keys는 봉투 수를 줄이는 후속 최적화로 남긴다.

## 2. 모델

| 항목 | 내용 |
|---|---|
| `conversations.kind` | `direct` \| `group` |
| `conversations.name` | 그룹 이름(1~64자), direct는 null |
| `conversation_participants` | 그룹은 N명. 생성자 포함, `hidden_at`은 사용자별 숨김 |
| 인원 제한 | 생성자 포함 20명 (`MAX_GROUP_MEMBERS`) |
| 중복 | 그룹은 중복 생성 허용(1:1만 재사용) |

## 3. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/conversations` | `{kind:"group", name, memberUserIds:[...]}` (1~19명) |
| GET | `/api/conversations` | 요약: `kind`, `name`, `peer`(direct), `members`(나 제외), `memberCount` |
| GET | `/api/conversations/:id` | 단일 요약(참여자만) |
| POST | `/api/conversations/:id/members` | `{userIds:[...]}` 참여자 추가(멱등) |
| GET | `/api/conversations/:id/devices` | 참여자 전체 활성 기기 공개키 |

오류: `INVALID_GROUP_MEMBERS`(400, 자기 자신/빈 목록), `USER_NOT_FOUND`(400),
`NOT_GROUP_CONVERSATION`(400), `GROUP_FULL`(409), `CONVERSATION_NOT_FOUND`(404, 비참여자).

## 4. UI

- 새 대화 모달: **1:1 / 그룹** 탭. 그룹 이름 + 아이디 검색으로 참여자 추가.
- 목록: 그룹 이름, `N명 · 종단간 암호화`, 그룹 아이콘.
- 헤더: 그룹 이름, 인원, 입력 중인 참여자 이름, **참여자 추가** 버튼(그룹만).
- 말풍선: 발신자 이름 표시. 삭제된 계정은 “삭제된 사용자”.
- 안전번호: 참여자 전체 기기 공개키로 계산. 기기/참여자가 바뀌면 번호가 바뀐다.

## 5. 한계

- **그룹 목록 갱신 지연**: 그룹 생성/참여자 추가를 WS로 push하지 않아 새 참여자의 목록은 최대 30초 뒤 갱신된다
  (현재 `GET /api/conversations` 30초 폴링).
- 그룹 이름 변경, 나가기, 관리자 역할, 초대 링크는 아직 없다.
- 그룹 이름·참여자 목록은 서버 메타데이터로 노출된다(메시지 내용만 E2E).
- 새 참여자는 과거 이력을 받지 못한다. 이력 이전은 별도 설계가 필요하다.

## 6. 검증

- 서버: 3인 그룹 팬아웃/복호화, 참여자 추가 후 재암호화(409), 새 참여자 과거 이력 차단, 멱등 추가,
  비참여자·direct 오류, 입력 검증
- E2E: 3인 그룹 생성 → 메시지/답장 → 새 참여자 목록·이력 → 그룹 안전번호 60자리
