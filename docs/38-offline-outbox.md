# 오프라인 전송 큐(아웃박스)

## 1. 동작

| 상황 | 동작 |
|---|---|
| 오프라인(`navigator.onLine === false`)에서 전송 | 요청을 시도하지 않고 **로컬 큐에 저장**, 입력창은 비워지고 "전송 대기 N건" 배너 표시 |
| 전송 중 네트워크 단절(fetch 실패) | 같은 방식으로 큐에 저장 |
| 대기 중인 메시지가 있을 때 새 메시지 전송 | **순서 보존**을 위해 똑같이 큐에 저장(먼저 보낸 것부터 전송) |
| 연결 복구 | `online` 이벤트 · 실시간(WS) 재연결 · 10초 간격 재시도로 **자동 전송** |
| 수동 재시도 | 배너의 **지금 재시도** 버튼 |
| 영구 실패(차단·상대 삭제 등 4xx) | 큐에서 제거하고 오류 문구 표시 |
| 로그아웃 | 큐 전체 삭제 |

## 2. 저장 형식

`client/src/lib/outbox.ts` — IndexedDB `onemoments-outbox` (사용 불가 시 메모리 폴백)

| 필드 | 설명 |
|---|---|
| `id` | `clientMessageId` (재전송 멱등성 키) |
| `conversationId` | 대화 |
| `text` | 복호화된 본문(전송 시 **다시 암호화**) |
| `kind` / `viewOnce` / `targetMessageId` | 수정·한 번 보기·답장 대상 |
| `createdAt` / `attempts` / `lastError` | 순서 보존과 재시도 기록 |

- 최대 **100건** 유지(넘치면 오래된 것부터 폐기)
- 같은 `id` 로 다시 넣으면 덮어쓴다(중복 방지)

> 프라이버시: 큐에는 **평문 본문**이 기기에 남습니다(초안·북마크와 동일한 정책). 로그아웃·자동 잠금 시 삭제됩니다.

## 3. 왜 큐에 넣을 때 암호화하지 않는가

수신자 기기 키를 가져오는 단계(`/api/conversations/:id/devices`)가 네트워크에 의존하고,
그룹 Sender Keys 는 **전송 성공 시점에 커밋**해야 키 체인이 어긋나지 않습니다.
그래서 큐에는 평문 의도를 저장하고, 재전송할 때 **순서대로 다시 암호화·커밋**합니다.

또한 대기 항목이 있으면 새 메시지도 큐를 거치게 해 **서버 도착 순서와 키 카운터 순서를 일치**시킵니다.

## 4. 범위 제한

- **첨부(이미지·파일·음성)** 는 큐에 넣지 않습니다. 업로드가 필요하므로 기존처럼 실패 시 재시도 버튼을 사용합니다.
- 자동 삭제·한 번 보기는 **서버 수신 시점** 기준이므로, 오프라인 동안 작성한 메시지는 도착 시점부터 계산됩니다.
