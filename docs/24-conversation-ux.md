# 대화 UX: 반응·답장·수정·삭제·검색

메신저 기본기를 높이는 4종 기능이다. 모든 **내용**은 기존 E2E 암호문 안에 두고, 서버에는 최소한의 **종류 메타데이터**만 저장한다.

## 1. 공통 모델: 메시지 종류(kind)

| 컬럼 | 의미 |
|---|---|
| `messages.kind` | `text`(일반·답장) / `reaction`(이모지 반응) / `edit`(수정 이벤트) |
| `messages.target_message_id` | 반응·수정·답장의 대상. self-FK `ON DELETE SET NULL` |

- 서버가 보는 것: `kind`, `targetMessageId`, 시각, 발신자/기기
- 서버가 못 보는 것: 일반 본문, 답장 인용, 이모지, 수정된 본문 — **모두 암호문 안**
- 반응/수정은 새 메시지 이벤트로 전송하므로 **기존 봉투·서명·sender key·멱등 경로를 그대로 재사용**한다.
- 반응·수정은 대화의 **unread 배지와 마지막 메시지 시각에서 제외**한다.

## 2. 기능별 동작

### 이모지 반응
- `kind="reaction"`, `targetMessageId`로 대상 지정
- 암호문 평문 형식: `{"emoji":"👍","op":"add" | "remove"}`
- 사용자별 **최신 반응 이벤트만** 유효하다(재전송/토글).
- 클라이언트가 복호화해 대상 메시지 아래에 이모지+인원수로 집계한다.
- 반응/수정 메시지를 대상으로는 반응할 수 없다(`text`만 허용).

### 답장(인용)
- `kind="text"` + `targetMessageId`(원문)
- 인용문을 별도로 저장하지 않고, 클라이언트가 대상 메시지를 로컬에서 복호화해 표시한다.
- 대상이 삭제되면 FK `SET NULL` 로 참조만 해제되고 답장 본문은 유지된다.

### 수정
- `kind="edit"` + `targetMessageId`(원문). **발신자만** 가능하고 대상은 `text` 메시지여야 한다.
- 클라이언트는 대상별 **최신 edit 이벤트**의 평문을 표시하고 원문 위에 "수정됨"을 표시한다.
- 원문 암호문은 남지만 화면에는 최신 수정본만 보인다(감사/복구 목적).

### 삭제: 모두에게서 전송 취소 / 나에게만 삭제
- `DELETE /api/conversations/:conversationId/messages/:messageId?scope=all|me`
- `scope=all`(기본값) — **발신자만**. 메시지 행, 기기 봉투(`message_keys`), 첨부 행·블롭, 대상에 달린 반응/수정 이벤트를 함께 삭제한다. 답장은 삭제하지 않고 `target_message_id`만 `NULL`로 만든다.
- `scope=me` — **참여자 누구나**. `message_deletions(message_id, user_id)` 행만 추가하고 메시지·봉투·첨부는 유지한다.
  - 해당 사용자의 이력 조회·읽지 않은 수·마지막 메시지 시각에서 제외한다.
  - 같은 사용자의 다른 기기에는 WS `message.hidden`(클라이언트에는 `message.deleted`로 전달)으로 즉시 알린다.
  - 상대방 화면에서는 그대로 보인다.
- `scope=all` 삭제 전에 읽음 커서를 남은 메시지로 보정한다(자동 삭제와 동일 로직 재사용).
- 클라이언트는 메시지 캐시·복호화 캐시·검색 인덱스에서 제거한다.

## 3-2. 서식과 링크

- 지원: `**굵게**`, `` `인라인 코드` ``, `http(s)` 링크, `@멘션`.
- HTML 을 직접 렌더하지 않고 React 요소로만 그리므로 **XSS 위험이 없다**(스크립트 실행 경로 없음).
- 링크는 **http/https 만** 링크로 만들고 나머지는 일반 텍스트로 표시한다. 새 탭 + `rel="noopener noreferrer nofollow"`.
- 입력창의 **B / `</>` 버튼**으로 선택 영역을 서식 기호로 감쌀 수 있다(선택이 없으면 자리표시자 삽입).
- 한계: 굵게 안에 링크·멘션을 **중첩 지원하지 않는다.** 링크 미리보기(Open Graph)는 서버 아웃바운드 요청이 필요해 도입하지 않았다.

## 3-1. @멘션

- 서버에 멘션 **메타데이터를 저장하지 않는다**. 본문의 `@username` 토큰만으로 표현한다(서버는 여전히 암호문만 보관).
- 클라이언트는 참여자 username 목록과 일치하는 토큰만 강조하고, 내 username이 포함되면 `나를 멘션` 배지를 표시한다.
- 입력창에서 `@` 뒤에 글자를 입력하면 참여자 자동완성 후보를 보여준다(그룹/1:1 공통).
- 알림 문구에는 멘션 정보를 넣지 않는다(푸시 payload에 내용 금지 원칙 유지).

## 3. 클라이언트 검색

- 서버 검색은 하지 않는다(평문 미보유).
- 복호화에 성공한 `text` 메시지의 본문·첨부 파일명을 **IndexedDB(`onemoments-search`)** 에 인덱싱한다.
- 사이드바 검색창(2자 이상)에서 부분 일치 검색, 결과 클릭 시 해당 대화로 이동한다.
- **로그아웃/자동 잠금 시 검색 인덱스를 삭제**한다.
- 커버리지: 이 기기에서 복호화된(로컬에 로드된) 메시지. "이전 메시지"를 불러오면 검색 범위가 넓어진다.

## 4. API / WS

| 종류 | 변경 |
|---|---|
| POST | `/api/conversations/:id/messages` body에 `kind?`, `targetMessageId?` 추가 |
| DELETE | `/api/conversations/:id/messages/:messageId?scope=all\|me` (`all`은 발신자, CSRF) |
| WS client | `message.send`에 `kind?`, `targetMessageId?` |
| WS server | `message.deleted { conversationId, messageIds[] }` 추가 |
| bus | `message.created` / `message.deleted` / `message.hidden` 이벤트 union (Redis 직렬화 포함) |

## 6. 한계

- 반응·수정·답장의 **대상 관계는 서버 메타데이터**로 노출된다(누가 어떤 메시지에 반응/수정했는지).
- 이전 버전 클라이언트는 반응/수정 이벤트를 일반 메시지처럼 표시할 수 있다(하위 호환).
- 검색은 로컬에 복호화된 범위만 대상이며, 서버·다른 기기와 동기화되지 않는다.
- 로그아웃/자동 잠금 시 인덱스를 지우지만, 브라우저가 비정상 종료되면 로컬 저장소에 남을 수 있다(브라우저 저장소 보호에 의존).
- 검색 결과는 대화로 이동만 하고 특정 메시지로 스크롤하지 않는다(후속 개선).
- 삭제는 복구할 수 없고, 이미 내려받은 첨부·화면 캡처는 회수할 수 없다.
- “나에게만 삭제”는 메타데이터로 숨기는 방식이라 원본·첨부가 서버에 남는다. 첨부 URL을 직접 아는 경우 다운로드 자체를 막지는 않는다.
- 자동 삭제는 대상 메시지 삭제 시 반응/수정 이벤트를 함께 정리하지만, 답장은 유지한다.
- 다중 인스턴스 **롤링 배포** 중 이전 인스턴스는 `message.deleted` 이벤트를 해석하지 못할 수 있으므로 함께 재시작한다.
